Mise en place d'une architecture distribuée, chiffrée et résiliente

1. Schéma de l'Architecture

L'infrastructure interconnecte le Site A (Robin) et le Site B (Nathan) via un tunnel WireGuard établi sur un réseau mobile 4G.

SITE A (Robin) SITE B (Nathan) 192.168.1.0/24 192.168.2.0/24 [ Web A1 | .11 ] ---+ +--- [ Web B1 | .11 ] | (Tunnel) | [ Web A2 | .12 ] ---+--- [ LB A ] <====> [ LB B ] ---+--- [ Web B2 | .12 ] (10.50.0.1) (10.50.0.2)

2. Plan d'Adressage

3. Tunnel WireGuard & Routage

Le routage est activé via net.ipv4.ip_forward=1. Le tunnel assure le chiffrement du flux inter-site.

Config /etc/wireguard/wg0.conf (Site A) :

[Interface] PrivateKey = <CLE_PRIVEE_ROBSERVER> Address = 10.50.0.1/24 ListenPort = 51820 PostUp = iptables -A FORWARD -i wg0 -j ACCEPT; iptables -t nat -A POSTROUTING -o enp0s3 -j MASQUERADE [Peer] PublicKey = <CLE_PUBLIQUE_NATHAN> AllowedIPs = 10.50.0.2/32, 192.168.2.0/24 Endpoint = <IP_NATHAN_4G>:51820

4. HAProxy & Sécurisation SSL

Redirection HTTP → HTTPS obligatoire et équilibrage vers les serveurs locaux.

backend web_servers balance roundrobin option httpchk GET / server web-local-1 192.168.1.11:80 check weight 100 server web-local-2 192.168.1.12:80 check weight 100 server web-remote-siteB 10.50.0.2:443 ssl verify none check backup weight 50

5. Filtrage Firewall (UFW)

Politique de sécurité appliquée sur les Load Balancers :

7. Analyse des Risques & Conclusion

L'utilisation de WireGuard combiné à HAProxy permet une résilience élevée. Le chiffrement AES assure que les données critiques transitant par le réseau public 4G sont protégées contre toute interception.
